# 0.4.9：七项测试反馈处理记录

发行版本：主应用 0.4.9 / 模块 0.3.16 / 内置 Root 载荷 0.1.6。

## 证据与判断

1. 附件来自小米 23049RAD8C / Android 13，主包 0.4.8、Root 载荷 0.1.4。Root 回执新鲜、钩子 `ready (25)`，但应用和系统均处于停止状态。日志有进程启动后的 `enabled=false`，没有本进程内的重新开始记录。只能确认导出时未模拟，不能把它说成 Root 未授权或钩子没加载。`unmatched=32` 也不能单独证明某个具体第三方业务失败。
2. vivo V2055A / Android 15 截图是另一台设备，主包版本未显示。`interrupt failed` 位于加载器附加后、第一次暂停目标线程阶段；随后 `target restoration failed` 为清理失败提示。这一步尚未执行远程载荷，无法由现有无 errno 信息定位具体内核、权限策略或进程状态原因。
3. 主应用使用高德 Android 地图和搜索 SDK。Android Key 的包名/SHA1 校验与 Web 服务 Key 的“数字签名”开关不同，不应为本应用修改其他工具共用 Key 的设置。应为 MockGeo 单独申请 Android 平台 Key，按应用内显示的签名和包名绑定。

## 本轮修改

- 路线模式从临时面板状态移到与路线草稿同寿命的 ViewModel；从地图预览返回时保留循环选择，载入已保存路线时一并载入循环模式。循环推进保留跨圈余量，增加已完成圈数，便于识别是否真的循环。新增平滑速度曲线下连续跨终点、暂停和恢复的回归。
- 高德授权错误按无效 Key、Android 安全码不匹配、平台不匹配、签名错误分别提示，保留错误码；Key 页面明确要求独立 Android 平台 Key，不要求开启 Web 数字签名。
- 增加用户主动触发的本机定位诊断采集：尝试 GPS/network/fused 当次定位，超时可展示标明来源与年龄的缓存。采集时要求停止本应用模拟，显示系统返回值及模拟标记，不把它保证为真实物理位置。结果仅在会话内保留，用户选择后才保存含精确坐标的 JSON，不合并入常规诊断或自动上传。
- 增加 0–300 步/分钟参数，0 表示保留默认运动波形、不覆盖计步回调。模块 0.3.16 在已勾选的客户端作用域中，按参数改变移动时的运动波形及计步回调速率；暂停移动停止增长。依赖系统提供传感器事件，不写入第三方运动平台或历史步数，不保证各应用的步数算法认可。
- Root 加载器记录 `PTRACE_SEIZE`、`PTRACE_INTERRUPT`、`PTRACE_DETACH` 的 errno，并区分未执行远程代码时的附加清理失败和修改寄存器后的恢复失败；主应用给出对应阶段说明。这是诊断与清理范围改进，尚不宣称解决 vivo 原机失败。
- Root 钩子已加载但未运行时明确提示需要在地图开始模拟；记录进程启动时清理旧会话。保留失联后停止的机制，不因昨日运行过而自动恢复模拟。
- 已存在可用 MockGeo LSPosed 通道时，Root 自检提供直接切换 LSPosed 模式的入口。独立 Root 加载器与驻留 LSPosed 的同进程叠加实验发现崩溃，保护仍保留；这属于当前实现限制，并非 Android 强制规定。没有通过删除保护来假称支持共存。

## 核验范围

220 项 JVM 测试通过：model 25、route 47、engine 56、data 9、module 69、app 14。涵盖平滑循环跨终点、暂停/恢复、步频与波形周期、旧协议兼容、时间戳异常以及 Root 错误阶段。主包 Release、模块 Debug 构建及 app/module/rootpayload Lint 通过。

发行目录为 `releases/github-v0.4.9/`，使用已验收候选原包，仅主包、模块和 SHA256SUMS。当前主包 39,153,205 字节（约 39.15 MB），保留 ARM 32/64 位；签名与既有版本一致，无私人地图 Key。主包 SHA-256：`fdab2f704c91c63f4e3efdcf3f4b7f9f84b0cfd61224daf81e85cc4274ace137`；模块 SHA-256：`1372e6fc98ad03e72a6bc962e0310ff5268b0e075eb62704871fde3f798a7868`。

Root 0.1.6 的 DEX 协议与原生 loader 已更新，包含供内部测试的隔离应用进程入口。`libmockgeo_root.so` 的运行段与 0.4.8 相同，但 loader 不同；校验脚本仅在显式 `--allow-root-loader-change` 时允许该文件变化，仍检查库运行段、去调试信息和内置摘要，不将新 loader 写成“原生代码未变”。

初次离线构建时没有 USB 设备。后续用户连接小米 15 / Android 16，完成下述验收，再按已通过范围发行。

## 后续真机与共存实验

- 初始候选 `3bd8abf4…` 已覆盖安装，原设置保留；循环选择在离开面板进入地图并返回后保持。定位采集显示结果、保存入口和清除结果通过，未导出精确坐标。
- 配合当时已加载的模块 0.3.15，60 秒标准系统接口及生命周期/停止检查通过。这不代表模块 0.3.16 的完整步频链路已验收。
- 在自有独立检查应用进程中，确认 LSPosed 2.2.1 (7912) / API102 和模块 0.3.15 已加载。第一次不同目标方法的 Root 加载、方法替换、恢复等 8 项测试通过。
- 加入已被 LSPosed 拦截的同一方法的叠加测试后，检查应用的 ART 后台校验线程发生 SIGSEGV。未获得完整回执。崩溃限制在检查应用进程，系统进程 PID 3801 保持不变。这不证明“仅取消 MockGeo 模块后一定崩溃”，但证明不能由前 8 项成功推断通用共存安全。
- 已撤回实验共存开关和 `system-compat` 系统入口；当前候选仍保留 App 侧和载荷侧的 LSPosed 驻留保护，不提供未经验证的共存开关。要支持用户仅取消模块的目标，还需要避免两个引擎对同一方法及 ART 生命周期的冲突。
- 最终候选的主应用 DEX 与已安装的初始候选逐字节相同，仅 Root 载荷、loader 和摘要不同。最终包安装、新 Root 独立模式、模块 0.3.16 和完整步频，以及原 vivo 故障机仍需继续验收；USB 在末段断开，未自动重连、重启或修改热点。

- 60 秒正常前台服务定位验收通过：GPS 60、network 80、fused 118，共 258 帧更新；最大间隔 1,025 ms，坐标、provider、模拟标记正确。一次性定位、WebView、PendingIntent、取消、注销、flush 和停止确认通过。
- 使用真实主界面创建短路线、选择循环和骑行速度，实测累计 14 圈；暂停前后的定位显示和圈数保持不变，恢复测试中圈数从 4 增加到 6。修改点均为测试用公共坐标，未保存测试路线。
