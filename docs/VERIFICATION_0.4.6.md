# 0.4.6 核验

主应用 0.4.6/code10，模块 0.3.14/code17，内置 Root 0.1.2/code3。已作为 GitHub v0.4.6 发布；发布前未在目标荣耀设备或纯 Root 环境完成真机验收。

## 本轮证据

用户的新截图显示荣耀 Magic6、Android 17/API37、LSPosed 2.2.0 (7854)/API102；导出诊断显示主应用 0.4.5、已安装模块 0.3.13、未收到系统回执。模块已勾选系统框架与荣耀扩展系统包。

此前页面截图包含旧版提示，但新的诊断已证明故障也出现在当前正式版。因此不能继续用主包过旧、API102 不满足或作用域未勾选解释故障。未收到回执本身不能区分模块入口未执行、钩子安装失败、控制命令失败和回执写入失败。

本轮没有连接 USB 设备，未取得该荣耀手机的 LSPosed 加载错误日志。不能确认扩展系统包承载定位服务，也不能确认其他模块冲突。

## 修改与边界

- 自检不再吞掉异常。检查结果和导出日志区分命令失败、读取失败、无回执、旧回执及后端/随机标识不匹配。
- 短暂等待延迟回执，并限制最多 450 ms；不重复发送 PING、不降低 Root 随机标识校验、不接受旧回执为成功。
- 模块在 `onModuleLoaded` 收到系统进程身份后启动有界服务发现，不再完全依赖 `onSystemServerStarting`。后者仍是主要入口。
- 荣耀/华为扩展系统包补充路径要求 system UID，并通过现有 `FrameworkAccess.localLocationService` 验证实际本地 `Binder` 实现 `ILocationManager`。只加载扩展系统包但没有本地定位服务时，不安装系统钩子；不 hook 远程代理、不复制加载系统服务 jar。
- 安装仍使用原来的幂等 HookInstaller 和关键入口检查，发现期限保持 65 秒。此为防御性兼容修正，尚无证据证明它解决了故障手机的具体加载问题。
- 加载入口、结果和警告/错误写入框架日志，日志后端异常不会中断系统钩子；逐帧调试信息只保留在 logcat。回执写入返回空、抛异常及缺少系统 Context 都有明确记录。普通应用的客户端钩子不再用于已识别的系统服务宿主。
- 诊断输出包名、用户空间和声明状态。主包继续保留 `ACCESS_MOCK_LOCATION`。权限声明只能证明标准候选条件之一，不能证明荣耀/HyperOS 的实际选择列表可见。
- Root 载荷共享日志代码和版本常量更新，原生注入流程未变；新载荷不能沿用旧版的纯 Root 真机通过结论。
- 图标按应用主题重绘：主应用启动图标（含 Android 13+ 单色主题图标与 roundIcon）、前台通知小图标，以及模块图标（不再引用 `sym_def_app_icon`）。仅资源与通知 `setSmallIcon` 变更，不涉及定位逻辑。

## 真机待验

1. 完整安装主包和模块；只在用户方便时手动重启加载新模块，不自动重启或操作热点。
2. 运行环境重新检查，核对实际加载 0.3.14、系统通道和关键定位入口；若失败，使用新增阶段日志与框架启动日志判断原因。
3. 核对目标 ROM 的开发者选项候选列表。LSPosed 模式本身不依赖选择标准模拟应用，两个现象分别验证。
4. 连接自有探针验证 last/current/updates、取消/注销、持续定位与停止恢复。不得用编译成功替代目标设备验收。

Release 仅提供主应用、模块和校验文件，内部探针/自动化 APK 不作为用户附件。
